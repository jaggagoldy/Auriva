APS-008 · Phase 1 — Product Blueprint · For Review · Final document

Interaction Patterns

How Auriva behaves — one consistent UX language for every control, surface, flow and clinical state. APS-002 defined how things look; APS-007 defined where they sit; this document defines what they do when touched. Every future screen is bound by these patterns.

01 · Foundations

Interaction principles & timing standards

Response-time budget
< 100msEvery press acknowledges instantly: state change, ripple-free (no material ripples), pressed style.
< 1sResult appears, or skeleton takes over (B6). No spinners in content areas.
> 1sNamed progress ("Verifying registration…") + the UI stays interactive elsewhere.
> 10s / asyncConvert to a background job with a status surface (e.g. KYC review card) — never a held spinner.
Motion
  • Durations: 150ms (hover, chips, toasts in), 250ms (drawers, sheets), 300ms (state-change row highlight). Easing ease-out in, ease-in out.
  • Motion explains causality only — nothing animates for delight in clinical contexts. prefers-reduced-motion collapses all motion to fades.
Write strategy — optimistic vs. pessimistic
Optimistic (apply now, sync behind)Mark read, toggle filters, reorder queue, notes autosave, check-in. Failure → revert + toast with retry.
Pessimistic (server confirms first)Sign Rx, publish lab result, payments, cancel appointment, consent grants. Button holds loading state; no UI change until confirmed.
Undo over confirm
  • Reversible actions execute immediately with a 5s Undo toast (skip patient, archive, mark read).
  • Confirm dialogs are reserved for: destructive (delete), clinical (sign, publish), outward-facing (notify patients), and money.
  • Clinical actions are never optimistic and never undoable-silently — reversal is a new, logged action.
02 · Controls

Buttons

  • States: default → hover (bg shift) → pressed (darken) → focus (ring, always visible) → loading → disabled. Loading replaces the label with a spinner at fixed width — buttons never resize mid-action.
  • One primary per view (APS-002). Everything else: secondary, soft, ghost. Destructive style only for destructive verbs.
  • Submit protection: on press the button disables and the request is idempotent — double-tap can never double-book or double-bill.
  • Disabled vs hidden: hidden when the role can't ever use it (N6); disabled only when a state makes it temporarily unavailable — with a tooltip saying why ("Select a slot first").
  • Icon-only buttons require tooltip (600ms delay) + aria-label. Minimum touch target 44px even when the glyph is 20px.
  • Verb labels: buttons say what they do — "Book appointment", "Sign & complete", never "OK" / "Yes" / "Submit".
Don't: stack two primaries · use danger color for emphasis · show a disabled primary with no explanation · let a loading button be re-clickable.
03 · Input

Forms & Validation

Form behavior
  • First field autofocused on open (desktop & drawers; mobile only inside flows).
  • Labels above fields, always visible — no floating labels, no placeholder-as-label.
  • ⏎ submits single-field steps; ⌘⏎ submits multi-field forms; Tab order follows visual order.
  • Formatting is automatic while typing (phone grouping, ₹ amounts); the user never types formatting characters.
  • Drafts: clinical and long forms autosave every 2s of idle + on blur; "Draft saved" chip timestamps it (B4 exempts these from guards).
  • Multi-step flows validate per step; Back never loses entered data; steps are revisitable before final submit.
Validation choreography
  • Never on first keystroke. Validate on blur; once a field has errored, re-validate on every change so the error clears the moment it's fixed.
  • Error anatomy: red border + 12.5px message below the field, replacing the helper text. Message says how to fix, not what failed ("Enter a valid 10-digit mobile number").
  • Submit with errors: scroll to first error, focus it, and summarize count for screen readers. The button un-disables — users may always attempt submit.
  • Async validation (phone dedupe, ABHA lookup): inline spinner in the field suffix, result within 1s; success may show a positive hint ("Existing patient — Ananya S. will be linked").
  • Warnings ≠ errors: amber, non-blocking ("Fee differs from price list"); errors block, warnings inform.
04 · Feedback

Loading & system feedback

  • Skeleton-first everywhere (B6): skeletons mirror the real geometry (APS-007 per-layout specs). After one shimmer cycle with no data (~3s), swap to a quiet "Still loading… Retry" state.
  • Spinners live only inside buttons and field suffixes. Full-page spinners do not exist in Auriva.
  • Streaming: where partial data is useful it renders progressively — slot grids fill in, search results append, insights charts draw when ready. Never block a page on its slowest widget.
  • Retry policy: failed reads auto-retry once silently, then show an inline error region with Retry. Failed writes never auto-retry — they surface immediately (toast for optimistic, inline for pessimistic).
  • Stale & live: realtime surfaces (queue, board) show "Updated 12:04" when the socket drops and a reconnect banner (z-500) if offline > 10s. Cached data is shown greyed, never hidden.
  • Success feedback ladder: in-place state change (best) → toast (when the result is elsewhere) → success screen (only ends of flows, e.g. booking confirmed).
05 · Finding

Search · Filters · Sorting · Pagination

Search
  • Debounce 250ms · min 2 chars (1 for numeric/phone) · matches highlighted in results.
  • ⌘K palette: results grouped by type, ↑↓ + ⏎, ⌘⏎ primary action, recents when empty (APS-006 §06).
  • In-list search boxes filter the current list only and combine with active filters (AND).
  • Clearing search restores prior scroll position, not the top.
Sorting
  • Column header click cycles asc → desc → default; arrow indicator on the active column only. Single-column sort in V1.
  • Every list declares a default sort with time-relevance (queues by position, appointments by time, registries by recent activity).
  • Sort is URL state (N5/B1) and persists per list per session (B3).
Filters
  • Applied filters render as removable chips (✕); "+ Filter" opens a popover of facets; desktop applies instantly, mobile sheets batch behind an Apply button.
  • "Clear all" appears with 2+ chips. Filter state is URL state — shareable, restorable, never a separate page (N5).
  • Facet options show result counts where cheap ("Confirmed · 12"); zero-count options remain visible but muted.
  • Saved views (org lists): name the current filter+sort set; role-private in V1.
Pagination
  • Tables paginate: 25 default (25/50/100), range label "1–25 of 412", pager keeps position on drawer open/close.
  • Infinite scroll only on patient-mobile feeds (timeline, notifications) with day separators as anchors.
  • Changing filters/sort resets to page 1; everything else preserves the page (B3).
06 · Surfaces

Tables & Cards

Tables (desktop ops)
  • Row click opens the drawer; interactive cells (chips with menus, ⋯) stop propagation. Hover reveals row actions; J/K + ⏎ mirror it for keyboard.
  • Bulk-select: checkbox column when batch actions exist; ⇧-click selects ranges; a sticky action bar replaces the filter bar while selection > 0.
  • Realtime changes patch the row in place with a 300ms teal highlight (B8); new rows slide in at their sorted position — the table never re-jumps under the user.
  • No inline cell editing in V1 — edits happen in the drawer, keeping validation and audit in one place.
Cards
  • Clickable cards: whole surface is the target; hover lift (desktop) only if clickable. Inner CTAs (Book slot) stop propagation.
  • Patient-mobile list cards support swipe actions (left: primary e.g. Reschedule; right: destructive e.g. Cancel) — always an accelerator, never the only path; the same actions live in the detail view.
  • Queue cards expose one-tap actions (Call in / Skip) directly — no drawer detour for the 90% case.
  • Long-press on mobile = the desktop right-click/⋯ menu (600ms, with haptic).

Behavior contract
  • Dialogs: focus trapped; initial focus on the least destructive action; Esc = cancel; scrim click does not close confirm dialogs (misclick safety). Destructive anatomy: named object + consequence line + verb buttons ("Cancel appointment", not "Yes").
  • Drawers: open 250ms; close via Esc, ✕, scrim, or back (B2); dirty content triggers the guard (B4). Drawer URLs are real (B1). A drawer never opens another drawer — inner navigation replaces content with a back arrow in the drawer header.
  • Nothing auto-dismisses a dialog — only user action or the operation completing does.
08 · Messaging

Notifications & Toasts

  • Toasts (z-500): bottom-left desktop, top mobile; 5s duration, 8s with an action (Undo/Retry); max 3 stacked, oldest collapses. Hover pauses the timer. Toasts confirm — they never carry errors that require action (those render inline at the point of failure).
  • Bell panel: opening marks visible items read (unread dot fades, count decrements); "Mark all read" for the rest. Items deep-link (X6) and back returns to origin (X7).
  • In-app urgent banners: time-critical events (You're next · Emergency added · e-sign failed) render an 8s banner below the top bar — a bell count alone is never the only signal for urgency.
  • Realtime etiquette (B8): another user's action updates data in place with the 300ms highlight; it never navigates, focuses, or opens anything on this user's screen.
  • Sound: off by default everywhere except the org Token Display (ORG-004) announcement chime.
09 · Clinical States

Appointment & Queue status — state machines

Status is sacred (APS-002 P3). These are the only allowed states and transitions, platform-wide. Every transition is logged with actor + timestamp, and every patient-visible change notifies the patient.

Appointment lifecycle
Requested→org/doctor approves→ Scheduled→patient confirms / auto→ Confirmed→reception check-in→ Checked-in→doctor calls→ In Consultation→ Completed
Exit transitionFromActorRules
→ CancelledRequested…ConfirmedPatient / OrgReason captured; slot reopens instantly; patient/org notified. Not allowed after Checked-in — use "revert check-in" first (logged).
→ No-showScheduled / ConfirmedSystemAuto after grace window (org-configurable, default 30 min post-slot); reception can override back to Checked-in same-day.
→ RescheduledRequested…ConfirmedEither sideModeled as new appointment linked to the old; history chain preserved.
  • Transitions are forward-only for actors; corrections (wrong check-in) are explicit reversions with reasons, visible in the audit log (SET-008).
  • Chips always render dot + label (never color alone), colors fixed per APS-002 — no workspace may restyle a status.
Queue lifecycle (per visit-day token)
Waiting→doctor calls→ Called→patient enters→ With Doctor→ Done
  • Called → Waiting: no response in 2 min re-queues at +2 positions, max twice, then Skipped (grey). Reception can restore a Skipped token to Waiting anytime.
  • Emergency: reception-only action; inserts at position 1 with mandatory reason; board shows red card; doctor gets an urgent banner. All displaced patients' ETAs update + notify.
  • Tokens never renumber. Positions recalculate; the printed/SMS token stays valid all day. Patient app shows position + ETA, both live.
  • Reorder (drag on board) is reception-only, optimistic, logged, and rate-limited to prevent thrash.
10 · Clinical Interactions

Medical Timeline · Prescription · Sharing

Medical timeline
  • Reverse-chronological, grouped by date; loads the last 12 months, older years lazy-load on demand ("2025 · 14 events").
  • Type filter chips (Visits · Rx · Labs · Vitals · Docs) — instant, combinable.
  • Tap: mobile expands the entry inline (accordion); desktop opens the entity drawer. Dot colors by event type (APS-002); source badge shows the providing org.
  • New events slide in with highlight if the timeline is open when they land (e.g. Rx right after a consult).
  • Same data, two voices: patient view uses plain language ("Blood test — mostly normal, iron low"); clinical views show terminology. The projection changes, the record never does.
Prescription preview
  • Dose pills use 1-0-1 notation with plain-text expansion on tap ("morning and night, after food").
  • Patient actions: Download PDF · Share (→ sharing flow) · Send to pharmacy. Signed state chip always visible; "signature pending" renders amber if e-sign is delayed (J2 recovery).
  • Doctor composer: search-add medicines (recents + templates first), ⌥R focus, template apply then edit, per-line dose/duration pills. Allergy conflict is a hard stop — proceeding requires an explicit override with a typed reason, logged on the Rx.
  • ⌘⏎ Sign & complete — pessimistic write; on success the queue advances automatically.
  • Signed prescriptions are immutable; corrections issue a superseding Rx linked to the original.
Sharing flow (records & consent)
  • Patient-initiated share: pick scope (whole record / a report / date range) → pick duration (24h · 7d · 30d) → generate link + QR. Default scope is always the minimum that satisfies the action.
  • Provider-requested consent (ABDM): doctor requests → patient gets push + in-app card stating who, what, why, how long → Approve / Modify scope / Deny. Approval unlocks within the consult in real time (J2).
  • Every access is logged and visible to the patient (PAT-015): who viewed what, when. Revoke is one tap, effective immediately, and confirmed with a toast.
  • Expiry is automatic and silent for the viewer, notified to the owner ("Your share with Dr. Mehta expired").
  • No dark patterns: consent requests never pre-select scopes, never nag more than once per request, and Deny needs no reason.
11 · Identity Flows

OTP Flow · Organization Switching

OTP flow
  • 6 boxes (48×56), first autofocused; typing auto-advances; backspace moves back; full-code paste fills all boxes; SMS auto-read on Android fills and pauses 1s before auto-submit (visible, cancellable).
  • Auto-submit on the 6th digit — no Verify button press needed (button exists as fallback).
  • Wrong code: boxes shake once (150ms), clear, refocus first box, inline error "Incorrect code — 2 attempts left".
  • Resend: 30s cooldown with visible countdown → resend → second resend offers voice OTP; after 3 failed codes, a 60s hold with a support link. Never a silent lockout.
  • "Change number" link is always present — mistyped numbers are the #1 OTP failure.
  • Same component everywhere: sign-in (L5), booking-embedded (L4 modal), re-auth on session expiry (B9), sensitive-action step-up (payout changes).
Organization / context switching
  • Sidebar-header popover (APS-006 §05): orgs then branches, searchable > 6, recents first; ↑↓ + ⏎.
  • Switch target: same module, new scope. Perceived < 400ms — chrome swaps instantly, lists skeleton, badges refetch. Current branch name is always visible in the sidebar header afterward.
  • Dirty work triggers the guard (B4) before switching; an in-progress flow blocks switching with "finish or discard".
  • Role may change with the org — the sidebar re-renders (N6) and, if the current module doesn't exist in the new role, lands on that role's home with a one-line explainer.
  • Workspace switching (identity change) stays separate in the profile menu (X1) with the same guard rules — the two switchers are never merged.
12 · Close-out

One language, enforced

The consistency contract
  • Every screen designed from here on must be expressible as: APS-007 layout shell + APS-002 template + these interaction patterns. A screen needing a new pattern amends this document first — patterns are never invented per-screen.
  • The same action always has the same trigger everywhere: row click = open, ⌘K = find, Esc = close, swipe = accelerate, chip = status. No exceptions per workspace.
  • Anything clinical is: pessimistic, confirmed, logged, immutable-with-supersession. Anything reversible is: instant, undoable, quiet.
