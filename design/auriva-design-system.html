01 · Foundations

Design Principles

Auriva sits between a receptionist with 40 patients waiting, a doctor with 3 minutes per consult, and a patient who may be scared and non-technical. Every principle serves one of them.

P1

Calm over clever

Healthcare is stressful. The UI is quiet, predictable, and never draws attention to itself. Whitespace is a feature. No gradients, no glass, no decoration without purpose.

P2

Speed is care

Every core workflow — check-in, prescribe, book — completes in ≤ 3 clicks. Receptionist and doctor flows are keyboard-first with global search (⌘K) everywhere.

P3

Status is sacred

In healthcare, ambiguity is dangerous. Appointment and queue states use one fixed, platform-wide color language. A status color never means two things.

P4

Patients own their data

Patient-facing UI uses plain language, large touch targets, and progressive disclosure. Medical jargon is translated; records are always exportable and legible.

P5

Accessible by default

WCAG 2.1 AA minimum. 4.5:1 contrast on all text, visible focus rings, 44px touch targets on mobile, full keyboard navigation, and status never conveyed by color alone.

P6

One system, four faces

Patient, Doctor, Organization and Marketplace share one token set and one component library. Layouts change per workspace; the language never does.

Style direction

Inspired by Apple, Linear, Stripe and Notion — engineered restraint, not visual excitement.

✓ We use

  • Generous whitespace and a strict 4px spacing grid
  • Inter typography with tight, confident headings
  • Soft layered shadows (never harsh borders + shadows together)
  • Rounded corners — 8px controls, 12–16px surfaces
  • One accent color (Auriva Teal) used sparingly
  • Real data hierarchy: name → status → time → detail

✕ We never use

  • Glassmorphism, blur cards, neon glows
  • Multi-color gradients or decorative illustrations in workflows
  • Gaming UI, badges-as-rewards, confetti in clinical contexts
  • More than one primary action per view
  • Red for anything except danger / emergency
  • Dense dashboards that need a manual to read

05 · Layouts

Workspace Layouts

Five reusable shells. Every future screen slots into one of these — no screen invents its own frame.

AS
Patient — Mobile-firstHeader · content feed · 4-tab bottom nav · FAB for booking
Doctor — DesktopSlim sidebar · queue left · active patient context right

Layout rules
  • Grid: desktop 12-col / 1200px max content / 24px gutters. Mobile 4-col / 16px margins.
  • Sidebars: Doctor 220px (slim, focus on patient), Organization 248px (deep nav with sections). Collapsible to 64px icon rail.
  • Detail views open in right drawers (400–480px), not new pages — receptionists never lose the list.
  • Patient mobile: bottom tab bar (max 4 tabs + center action), content cards full-width, 16px radius.
  • Page background is #F5F7FA; content surfaces are white cards. Never white-on-white.
06 · Navigation

Product Information Architecture

Four workspaces, one account system. A user can hold multiple roles (a doctor is also a patient); the workspace switcher lives in the top-left account menu.

PATIENT · mobile-first

  • Home — next appointment, active meds, quick actions
  • Care — appointments, queue status, bookings
  • Health Records — timeline, prescriptions, labs, vitals
  • Family — linked members, switch profiles
  • Profile — ABHA, insurance, settings (in header)
  • Center action: + Book (doctor / lab / pharmacy)

DOCTOR · desktop-first

  • Today — live queue + current patient (default view)
  • Schedule — calendar, slots, availability
  • Patients — my patient list, records
  • Consults — notes, prescriptions, follow-ups
  • Earnings — payouts, statements
  • Settings — profile, clinics, fees

ORGANIZATION · desktop

  • Front Desk — check-in, queue board, walk-ins
  • Appointments — all bookings, calendars per doctor
  • Patients — registry, records, ABHA linking
  • Doctors & Staff — roster, schedules, roles
  • Departments — OPD, diagnostics, pharmacy modules
  • Billing — invoices, insurance, settlements
  • Insights — occupancy, revenue, wait times
  • Settings — org profile, branches, permissions

PUBLIC MARKETPLACE · web, SEO

  • Search — doctors, clinics, hospitals, labs, pharmacies
  • Speciality hubs — cardiology, derma, pediatrics…
  • Provider profiles — verified info, slots, reviews
  • Book — guest booking → OTP → becomes patient account
  • For Providers — join Auriva (doctor / org onboarding)
  • Top nav only — no sidebar, fully crawlable
