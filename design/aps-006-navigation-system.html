APS-006 · Phase 1 — Product Blueprint · For Review

Navigation System

The complete wayfinding specification for Auriva across desktop, tablet and mobile — every navigation surface, switcher, search behavior and keyboard path, with exact responsive transformation rules. Built on the APS-003 architecture and APS-004 journeys. Specification only; screen design comes later.

01 · Navigation Model

One system, three devices, four workspaces

Each workspace has exactly one primary navigation surface per device class. Nothing else competes for wayfinding. This matrix is the master rule — every later section details one cell of it.

WorkspaceDesktop ≥1024Tablet 768–1023Mobile ≤767
MarketplaceTop bar + inline searchTop bar + inline searchTop bar (condensed) + search sheet
PatientTop bar + left rail (same 4 sections)Bottom tabs + top barBottom tabs (4 + Book) + top bar
DoctorSlim sidebar 220px + top barIcon rail 64px + top barBottom tabs (Today · Schedule · Patients · More)
OrganizationSectioned sidebar 248px + top barIcon rail 64px + top barDrawer nav (hamburger) — view-mostly
Model rules
  • Primary nav = L1 modules only (APS-003). L2 lives inside the page (tabs, sub-lists); L3+ is reached from lists. Navigation never shows more than one level.
  • Device class is capability, not punishment: mobile Doctor/Org surfaces cover the on-the-go subset (check a queue, approve a request) — full operation remains desktop-first by design.
  • The patient product is mobile-first; its desktop view is an adaptation, never the reverse. Doctor/Org are the opposite.
  • Every surface carries the same four utilities: search, quick action, notifications, profile — always in the same corner of the screen per device.
02 · Top Navigation

Top Navigation

Two variants: the public marketplace bar (brand + conversion) and the app bar (context + utilities). Both are 56px tall, sticky, white with a bottom hairline — never colored, never translucent.

Anatomy — marketplace top bar
1Logo 2Inline search — doctors, hospitals, labs 3For Providers 4Sign in / Avatar
1 · Logo — always returns to marketplace home (N3). 32px mark + wordmark; mark only ≤767px.
2 · Search — inline field, expands on focus with recents + suggestions; collapses to an icon opening a full-screen sheet on mobile.
3 · For Providers — the supply-side entry; text link, never a button (patients must not misclick it).
4 · Session — signed out: primary button. Signed in: avatar menu (§08) with "Open my Auriva" as the first item.
Anatomy — app top bar (all workspaces)
1Context: page title / breadcrumb (L3+) 2⌘K search trigger 3Quick action 4Bell 5Avatar
1 · Context zone — page title on L1/L2; breadcrumb trail replaces it on L3+ (APS-003 §08). Never both.
2 · Search trigger — a quiet input-shaped button showing ⌘K; opens the command palette (§06). Center-aligned on desktop, icon on ≤1023px.
3–5 · Utilities — fixed order, fixed corner, all workspaces: quick action (§09), notifications (§07), profile (§08). Muscle memory is a feature.
Behavior
  • Sticky at all times; content scrolls beneath. No hide-on-scroll — in clinical software the exits never move.
  • On scroll > 0 the hairline gains shadow-xs to separate from content; no other change.
  • The bar never hosts page actions (save, filter). Those belong to the page. The bar is wayfinding + utilities only.
03 · Side Navigation

Side Navigation

The desktop backbone for Doctor and Organization. Two widths, one anatomy: switcher on top, L1 items in the middle, account anchored at the bottom.

1Org / branch switcher 2L1 nav items (+ sections) 3Utility items 4Collapse toggle · profile
1 · Switcher zone — Organization: org avatar + branch switcher (§05). Doctor: clinic-context selector when multi-affiliation, otherwise just the workspace label.
2 · Items — 36px rows: 20px icon + 13px label + optional count badge. Active = teal-50 bg + teal-700 text (the only colored state). Organization groups items under OPERATE / MANAGE / UNDERSTAND / CONFIGURE section headers; Doctor has 6 flat items, no sections.
3 · Utilities — Settings, Help. Visually separated, always last.
4 · Footer — collapse toggle ([) and the signed-in user chip.
Rules
  • Widths: Organization 248px · Doctor 220px · collapsed icon rail 64px (icons + tooltips, sections become dividers). Collapse state persists per user per device.
  • Role-scoping (N6): items the role can't use don't render — a receptionist's sidebar is 4 items, not 9 greyed ones. Section headers with zero visible children disappear.
  • Badges: numeric counts only for actionable queues (Requests 3, Worklist 12). Max shown "99+". No red dots for "new stuff" noise.
  • One active item always. L3 detail pages highlight their owning L1 module.
  • No nested expanding trees. If an L1 needs sub-navigation, it renders as in-page tabs — never accordion sidebars.
04 · Bottom Navigation

Bottom Navigation

The patient's primary surface on mobile and tablet, and the doctor's mobile fallback. Fixed, always visible, thumb-first.

Anatomy — patient bottom bar
1Home 2Care 3+ Book 4Records 5Family
1/2/4/5 · Tabs — 24px icon + 10px label, both always visible (icon-only tabs fail non-technical users). Active = teal-600 icon + label; inactive = slate-400.
3 · Book action — raised 36px circular primary button, not a tab: it opens the T6 booking flow as a sheet and never shows an active state.
Rules
  • Hit targets 56px tall full-width per tab; safe-area padding on gesture-nav devices.
  • Always visible — never hides on scroll; flows (T6) and full-screen media are the only surfaces that cover it.
  • Re-tap = reset: tapping the active tab scrolls to top / pops the tab's stack to its root. Tab stacks are preserved when switching tabs.
  • Badges: Care shows a dot only on visit day (live queue active). Numeric badges are reserved for the bell, not tabs.
  • Family context banner: when browsing as a family member, a persistent banner sits above the bar ("Viewing: Ravi · Switch back") — context is never silent.
  • Doctor mobile: Today · Schedule · Patients · More (More = sheet with Consults, Earnings, Settings). Same geometry, no center action.
05 · Switchers

Workspace & Organization Switchers

Two different jobs: the workspace switcher changes who you are acting as (rare, deliberate); the org/branch switcher changes which floor you're standing on (frequent, lightweight).

Workspace switcher — in the profile menu only (X1)
  • Renders only for multi-role accounts; single-role users never see it.
  • Lists workspaces as identity cards: "Patient — Ananya" / "Doctor — Dr. Mehta · 2 clinics" / "Apollo Koramangala — Receptionist".
  • Switching is a full context change: new namespace, new nav, landing on that workspace's home (N3). Unsaved-work guard applies (§12).
  • Last-used workspace is remembered per device and becomes the sign-in default; deep links override it for one session.
  • Keyboard: ⌘⇧O opens it from anywhere.
Organization / branch switcher — sidebar header
  • Shown when the user belongs to 2+ orgs or an org has 2+ branches; single-context users see a static label.
  • Two-level popover: organizations, then branches; searchable beyond 6 entries.
  • Switching swaps the {orgId} scope and re-scopes every list and badge; it does not change the current module (Front Desk stays Front Desk).
  • Role may differ per org — the sidebar re-renders to the new role's items (N6).
  • Current branch is always visible in the sidebar header — never only in a menu.
  • Doctor equivalent: clinic-context pills on Today/Schedule filter queue and slots per affiliation.
06 · Search

Search & Global Search (⌘K)

Two search systems, deliberately separate: public marketplace search (a destination) and the in-app command palette (an accelerator). They never share UI or index.

Marketplace search
  • A visible, prominent field — the product's front door, never hidden behind an icon on ≥768px.
  • Query model: what (speciality, doctor, symptom, test) × where (locality). Results at MKT-002 with type tabs; filters mutate URL state (N5).
  • Suggestions while typing: specialities first, then providers, then content. Recent searches for returning visitors.
  • Zero results is a routing moment, not a dead end: nearby localities, sibling specialities, "browse all doctors in {city}".
Global search — the ⌘K command palette (all app workspaces)
WorkspaceIndexed entitiesInline commands
PatientMy appointments, prescriptions, reports, doctors, family members"Book…", "Show my meds"
DoctorMy patients, consults, prescriptions, schedule days"New Rx for…", "Block time off"
OrganizationPatients (phone/name/MRN), appointments, tokens, invoices, doctors, staff"Check in…", "New walk-in", "Today's collections"
  • Open: ⌘K / Ctrl K, or the top-bar trigger. Closes on Esc, restoring focus to where it was.
  • Result anatomy: icon + primary line + context line + type chip; grouped by entity type; max 5 per group with "see all" expanding to the owning list screen with the query applied.
  • Ranking: exact ID/phone match first, then prefix, then fuzzy — recency-weighted. A receptionist typing 4 digits of a phone number sees the patient in < 200 ms (perceived).
  • Selection: ↑↓ to move, ⏎ to open (drawer or page per its type), ⌘⏎ to open the primary action directly (e.g. straight into Check-in).
  • Scope: strictly the current workspace + current org scope. No cross-workspace results, ever (X3).
  • Empty state teaches: shows the top 5 commands and recent items for this role.
07 · Notifications

Notifications

One bell, one panel, per workspace — surfacing the shared notification module (APS-003 §04) with role-appropriate content and X6 deep-linking.

  • Placement: top-bar bell, position 4 (§02) on all devices; patient mobile keeps it in the top bar (tabs are for places, not streams).
  • Badge: numeric unread count, max "99+". Urgent operational alerts (emergency queue jump, e-sign failure) turn the badge red; everything else is neutral slate.
  • Panel: 380px popover on desktop; full-height sheet on mobile. Grouped Today / Earlier. Each item: icon + one-line summary + relative time + status chip where relevant.
  • Tap → deep link to the entity's canonical location in this workspace (X6); back returns to the panel's origin (X7). Items auto-mark read on open; "mark all read" available.
  • Channel escalation is invisible here: push/SMS/WhatsApp routing happens server-side per preferences (NOT-003); the in-app centre is always the complete record.
  • Live region: time-critical items (You're next · Patient waiting) also render as an in-app banner for 8s — never only as a bell count.
  • No marketing content in the bell. Ever. Promotions live elsewhere or nowhere.

Focus & accessibility rules
  • Visible focus ring always (--shadow-focus, APS-002) — never suppressed, keyboard and pointer alike.
  • Skip link ("Skip to content") is the first tab stop on every page; sidebar and top bar are single tab stops with arrow-key roving inside (WAI-ARIA menu/toolbar patterns).
  • Overlays trap focus (drawer, dialog, palette); on close, focus returns to the triggering element. Queue auto-advance moves focus to the next patient card.
  • Tab order follows visual order; drawers insert after the triggering row, not at document end.
  • Shortcuts are remappable later — the map above ships as the default layer, discoverable via ⌘/ and shown in tooltips.
11 · Responsive Rules

Responsive Navigation

Three breakpoints, deterministic transformations. Navigation morphs by replacing surfaces, never by hiding capabilities silently — anything dropped from chrome remains reachable via ⌘K or More.

  • Breakpoints are tokens: --bp-md: 768px, --bp-lg: 1024px, --bp-xl: 1440px (≥1440 widens content, never adds nav).
  • Input, not just width: touch devices get 44px minimum targets and swipe gestures regardless of viewport; pointer devices get hover states and shortcuts.
  • State survives resize: a drawer open at desktop becomes the full-screen page at mobile width with the same URL — rotation never loses work.
  • The Org token display (ORG-004) is chrome-free at every size — it is a broadcast surface, not a navigable one.
12 · Behavior

Navigation Behavior

The contract for how movement feels — state, history, guards and transitions. These rules bind every screen designed after this document.

RuleBehavior
B1URL is the source of truth. Every location — including active tab, open drawer, filters and search query — is representable as a URL. Refresh reproduces the exact view; every view is shareable within permission scope.
B2Back is sacred (X7). Browser/OS back always returns to the previous location with list state (filters, scroll, selection) restored. Drawers close on back before the page changes. Flows (T6) treat back as "previous step", with an explicit exit confirm.
B3State preservation: per-list filter and scroll state persists for the session; per-tab stacks persist on patient mobile. "Reset" is always explicit (re-tap tab, Clear all), never a side effect.
B4Unsaved-work guard: leaving a dirty form/consult prompts save/discard — except autosaved surfaces (consult notes, drafts), which navigate freely and say "Draft saved".
B5Deep links resolve through permissions: a link into another org/role lands on a clean "no access — switch identity?" screen offering legitimate identities (X1/X3). Never a blank 403.
B6Loading is skeleton-first: navigation paints the destination's layout instantly with skeletons (APS-002); chrome never blocks on data. Slow queries surface progress in-page, not as a frozen nav.
B7Transitions are quiet: 150ms fades/slides on drawers and sheets; zero animation on primary-nav changes on desktop. Motion respects prefers-reduced-motion.
B8Realtime never yanks navigation: queue/board updates re-render in place; if the focused item changes state, a subtle highlight explains what moved. The user is never auto-navigated by someone else's action — banners invite, they don't push.
B9Session expiry preserves intent: re-auth via OTP overlay returns the user to the same URL with state intact — critical for a receptionist mid-queue.
